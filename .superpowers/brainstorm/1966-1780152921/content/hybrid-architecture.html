Arquitetura híbrida: o melhor dos dois mundos

Script para batch previsível, ADK para interação sob demanda

📅 Modo Batch (hoje, mantém igual)
⏰ Schedule 8h → main.py
→ IMAP busca ontem (~50 emails)
→ 1 chamada Gemini (tudo junto)
→ Labels + archive via IMAP
→ Digest HTML → Telegram
~$0.003/dia · previsível · rápido
+
💬 Modo Interativo (novo, ADK)
📱 Mensagem no Telegram → agente
→ ADK interpreta o pedido
→ Chama fetch_emails(filtro)
→ Responde, age, busca específico
→ Resposta direta no Telegram
~$0.001-0.005/query · flexível

Exemplos de uso do modo interativo

"Lucy, tem algum email importante que eu esqueci de responder essa semana?"
→
fetch_emails(days=7, action="responder", priority="high")
→ filtra → lista 3 emails
"Arquiva tudo de newsletter que chegou hoje"
→
fetch_emails(today=True)
→ filtra newsletters
→ archive(uid) × N
→ "Arquivei 8 newsletters."
"O que o banco me mandou no mês passado?"
→
fetch_emails(days=30, category="Finanças")
→ filtra remetente banco
→ sumariza

Como as peças se conectam no n8n

Workflow atual — não muda
Schedule (8h)
↓
Code node → spawnSync(lucy/main.py)
↓
Telegram node → envia digest
Workflow novo — interativo
Telegram Trigger (mensagem do usuário)
↓
Code node → spawnSync(lucy/agent.py --query "...")
↓
Telegram node → envia resposta
lucy/main.py — continua igual (batch)
lucy/agent.py — novo arquivo ADK (interativo)
lucy/tools.py — funções compartilhadas entre os dois
O padrão: extraia a lógica de acesso (IMAP, Notion, etc.) para tools.py compartilhado. O main.py usa direto (barato, batch). O agent.py usa via ADK (flexível, interativo).
